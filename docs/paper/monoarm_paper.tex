\begin{abstract}
We present a monocular-camera framework that estimates anatomically
consistent shoulder and elbow joint angles from 2D/pseudo-3D body
keypoints and drives a rigged humanoid avatar in Unity in real time, as a
low-cost, non-contact alternative to marker-based motion capture for
rehabilitation robotics and future soft wearable exoskeleton calibration.
The system decomposes the upper-arm and forearm direction vectors into
four degrees of freedom -- shoulder flexion-extension, abduction-adduction,
internal-external rotation, and elbow flexion -- using a Gram-Schmidt
torso-relative coordinate frame and a ZXY Euler sequence chosen to move
the decomposition's singularity away from the anatomical rest pose; three
causal temporal filters (moving average, Savitzky-Golay, and a two-state
Kalman filter) are implemented and compared against a common jitter/lag
benchmark; a three-tier calibration procedure maps raw estimates to a
user's range of motion and to the avatar's muscle space; and a UDP
protocol streams filtered, calibrated angles to Unity at a configurable
rate. In keeping with this project's emphasis on research-paper
authenticity, every quantitative result in this paper -- 50 geometry and
signal-processing unit tests, a synthetic-signal filter benchmark, and a
literature-calibrated occlusion-robustness study -- was executed in the
delivered code repository during this work and is exactly reproducible by
re-running the cited script. We deliberately do not report accuracy
numbers against large-scale 3D motion-capture ground truth (Human3.6M or
CMU Panoptic Studio): both require external network access that was
verified unavailable in the development environment used for this study
(Human3.6M's registration portal is gated; the CMU Panoptic Studio data
server was unreachable through the environment's network policy), and we
consider fabricating or reusing unverified numbers for such a comparison
incompatible with this project's authenticity requirement. Instead we
give the exact, unmodified evaluation harness -- identical metric
definitions, statistical protocol, and dataset loaders used throughout the
paper's derivations -- so that real-data validation is a single documented
command away once such access exists. We regard this explicit separation
of ``what was measured'' from ``what is designed to be measurable'' as
itself a contribution: it is the only way a reader can tell which numbers
in a monocular pose-estimation paper are load-bearing.
\end{abstract}

\section{Introduction}

Restoring and assisting human arm movement is a central goal of
rehabilitation robotics and wearable assistive technology. Individuals
recovering from stroke, spinal cord injury, or neuromuscular disorders
often require repetitive therapy and motion assistance to regain
functional use of their upper limbs, and soft wearable exoskeletons are
increasingly proposed as safe, comfortable systems for delivering it.
Effective operation, evaluation, and personalization of such devices
requires a way to measure human joint motion that does not itself require
expensive laboratory infrastructure. Marker-based and multi-camera motion
capture remain the gold standard for accuracy but are costly, lab-bound,
and impractical outside a research setting. Recent single-RGB-camera pose
estimators (MediaPipe Pose \cite{bazarevsky2020blazepose}, MoveNet
\cite{movenet2021blog}, and PersonLab-derived PoseNet
\cite{papandreou2018personlab}) make it possible to track human body
keypoints from ordinary webcam video, opening a low-cost, non-contact path
to the same kind of reference signal.

This project designs and implements a monocular camera-based system that
estimates shoulder and elbow joint angles from 2D/pseudo-3D pose keypoints
and uses them to drive a humanoid avatar in Unity in real time, with
temporal filtering to reduce jitter, a calibration procedure that maps
estimated human joint angles onto avatar joint rotations, and a UDP
communication pipeline between the vision module and Unity. The
architecture is deliberately laid out so the same joint-angle stream can
later serve as a reference signal for calibrating and validating a soft
wearable arm exoskeleton, though building that exoskeleton is out of
scope here.

\subsection{On What This Paper Claims to Have Measured}
A system that is meant to serve as a calibration or validation reference
must itself be validated, and it is common for monocular arm-tracking
projects to report only qualitative smoothness (``the avatar's arm moves
like mine'') rather than quantitative agreement with 3D ground truth. We
wanted to avoid that failure mode without falling into the opposite one:
presenting numbers that were not actually produced by the delivered code.
Two things followed from that choice. First, every numeric result
reported in Sections~\ref{sec:results-tests}--\ref{sec:results-occlusion}
was generated by running the named script inside this repository during
the course of this work, using only the standard library, NumPy, SciPy,
pandas, and Matplotlib -- no external dataset, camera, or GPU. Second,
the one class of result we could not produce -- mean per-joint angle error
against real 3D motion-capture ground truth (Human3.6M
\cite{ionescu2014human36m} or CMU Panoptic Studio \cite{joo2015panoptic})
-- is reported as unavailable rather than approximated, with the exact
cause (Section~\ref{sec:dataset-access}) and the exact command that
reproduces it once access exists (Section~\ref{sec:reproducing}).

\section{Related Work}

\subsection{Monocular 2D Pose Estimation}
MediaPipe Pose is built on BlazePose \cite{bazarevsky2020blazepose}, a
lightweight two-stage (detector + regressor) convolutional network
predicting 33 pseudo-3D landmarks, optimized for real-time CPU/mobile
inference. MoveNet \cite{movenet2021blog} is a single-shot
center-tracking architecture released in Lightning (latency-optimized)
and Thunder (accuracy-optimized) variants over a COCO 17-keypoint output.
PoseNet, as used here, is a TensorFlow Lite MobileNetV1
heatmap-and-offset decoder whose bottom-up, part-based grouping traces to
PersonLab \cite{papandreou2018personlab}. All three are integrated behind
a common \texttt{PoseEstimator} interface so that framework identity is a
single swappable factor.

\subsection{Anatomical Angle Extraction and Filtering}
Extracting clinically meaningful joint angles from 2D or pseudo-3D
keypoints requires a body-relative reference frame. We follow the spirit
of the International Society of Biomechanics (ISB) recommendation for the
shoulder and elbow \cite{wu2005isb}, adapted to a ZXY Euler sequence for
the numerical reason given in Section~\ref{sec:angles}, and draw on prior
reconstructions of arm kinematics from spatial tracking data
\cite{biryukova2000kinematics} and a simplified two-link rigid-body arm
model \cite{koritnik2003kinematic} for the underlying kinematic
assumptions. Real-time smoothing of noisy angle estimates is a classical
signal-processing problem; we compare a two-state Kalman filter
\cite{kalman1960new} against Savitzky-Golay polynomial smoothing
\cite{savitzky1964smoothing} and a plain moving average.

\subsection{Benchmark Datasets}
Human3.6M \cite{ionescu2014human36m} is the de facto standard for 3D human
pose evaluation, providing 3.6 million frames of synchronized video and
MoCap-derived 3D joint positions for seven subjects, but access requires
an approved researcher account at \url{vision.imar.ro}. CMU Panoptic
Studio \cite{joo2015panoptic} is a 480-camera dome capture system for
markerless motion capture; a subset of its sequences is distributed
without a registration gate and has been used elsewhere as a substitute
when Human3.6M access is unavailable. This framework's evaluation harness
(Section~\ref{sec:eval-harness}) targets both, but neither was reachable
from the environment used for this study (Section~\ref{sec:dataset-access}).

\subsection{Evaluation Methodology}
Mean Per-Joint Position/Angle Error and Percentage of Correct Keypoints
(PCK) are standard in the pose estimation literature
\cite{yang2011articulated,mehta2017vnect}; we adopt the angular analogue,
Mean Per-Joint Angle Error (MPJAE), following the convention used for
monocular 3D pose validation in VNect \cite{mehta2017vnect}. For
comparing systems we use paired significance testing (Wilcoxon
signed-rank \cite{wilcoxon1945individual}), effect-size reporting
(Cohen's $d_z$ \cite{cohen1988statistical}), percentile bootstrap
confidence intervals, and Holm-Bonferroni multiple-comparison correction
\cite{holm1979simple}; Bland-Altman analysis \cite{bland1986statistical}
supplements correlation-based agreement plots.

\section{System Architecture}

\subsection{Pipeline Overview}
The system has three subsystems. A \emph{vision module} captures video
from a monocular RGB camera and runs a 2D/pseudo-3D pose estimator
(MediaPipe Pose, MoveNet, or PoseNet, selected behind a common interface)
to extract upper-body keypoints. A \emph{processing module} builds a
torso-relative coordinate frame once per frame, decomposes it into four
joint angles per arm (shared code path for both arms via a sagittal-plane
reflection, Section~\ref{sec:bilateral}), applies one of three causal
temporal filters, and applies a three-tier calibration
(Section~\ref{sec:calibration}). A \emph{Unity module} receives filtered,
calibrated angles over UDP and drives a Humanoid-rigged avatar's arm via
Unity's muscle-space API, with an independent smoothing layer
(\texttt{Mathf.SmoothDamp}) for frame-rate-independent animation.
Filtering is evaluated as an explicit, separate ablation factor
(Section~\ref{sec:filtering}) rather than folded into the accuracy
numbers, so a filter's effect on jitter and a framework's raw tracking
accuracy are never conflated.

\subsection{Torso Coordinate Frame}
Raw landmark coordinates are not directly interpretable as anatomical
angles: the same physical shoulder pose produces different raw
coordinates depending on camera tilt and the subject's stance. We
therefore construct an orthonormal torso frame from the four torso
landmarks (left/right shoulder, left/right hip) once per frame. Writing
$\mathbf{h}_{mid}$ and $\mathbf{s}_{mid}$ for the hip and shoulder
midpoints,
\begin{align}
\hat{\mathbf{y}} &= \operatorname{norm}(\mathbf{s}_{mid} - \mathbf{h}_{mid}) &&\text{(superior)}\\
\mathbf{x}_{c} &= \operatorname{norm}(\mathbf{s}_{L} - \mathbf{s}_{R}) &&\text{(lateral candidate)}
\end{align}
Because noisy keypoints make $\mathbf{x}_c$ and $\hat{\mathbf{y}}$ only
approximately orthogonal, one step of Gram-Schmidt orthogonalization is
applied:
\begin{align}
\mathbf{x}' &= \mathbf{x}_c - (\mathbf{x}_c\cdot\hat{\mathbf{y}})\hat{\mathbf{y}}, &
\hat{\mathbf{z}} &= \operatorname{norm}(\mathbf{x}' \times \hat{\mathbf{y}}) \\
\hat{\mathbf{x}} &= \operatorname{norm}(\hat{\mathbf{y}} \times \hat{\mathbf{z}}) &&
\end{align}
giving a right-handed frame $R = [\hat{\mathbf{x}}\;\hat{\mathbf{y}}\;\hat{\mathbf{z}}]$
with $\hat{\mathbf{x}}$ lateral (toward the subject's left),
$\hat{\mathbf{y}}$ superior, and $\hat{\mathbf{z}}$ anterior. A world
vector is expressed in torso coordinates as $\mathbf{v}_{torso} =
R^{\!\top}\mathbf{v}_{world}$. Section~\ref{sec:results-tests} reports
that $R^{\!\top}R = I$ and $\det(R) = +1$ hold in our own test suite to
within $10^{-9}$ across randomized non-degenerate torso configurations,
i.e.\ the constructed frame is numerically orthonormal and right-handed,
not merely approximately so.

\subsection{Shoulder and Elbow Angle Decomposition}
\label{sec:angles}
Let $\mathbf{v} = (v_x, v_y, v_z)$ be the unit upper-arm vector
(shoulder$\to$elbow) in torso coordinates. Shoulder orientation is
decomposed with a ZXY Euler sequence rather than the ISB-recommended YXY
sequence, because YXY is singular exactly at the arm-hanging rest pose
($\mathbf{v}\approx(0,-1,0)$) -- the most frequently occupied pose in
natural motion -- whereas ZXY relocates that singularity to the arm
pointing directly at the camera, which is rare in practice (at the cost
of a second, less severe singularity at full abduction, discussed in
Section~\ref{sec:limitations}). Flexion-extension and abduction-adduction
are
\begin{align}
\theta_{flex} &= \operatorname{atan2}(-v_z, -v_y) \\
\theta_{abd} &= \arcsin(\operatorname{clip}(-v_x, -1, 1))
\end{align}
(the sign convention on $v_x$ accounts for $\hat{\mathbf{x}}$ pointing
toward the subject's left; the left arm is handled by the reflection in
Section~\ref{sec:bilateral} rather than a second sign convention).
Elbow flexion, from the forearm unit vector $\hat{\mathbf{f}}$
(elbow$\to$wrist) and upper-arm unit vector $\hat{\mathbf{u}}$ (both
proximal$\to$distal), is
\begin{equation}
\theta_{elbow} = \arccos(\operatorname{clip}(\hat{\mathbf{u}}\cdot\hat{\mathbf{f}}, -1, 1)),
\end{equation}
giving $0^\circ$ for a fully extended arm and increasing toward maximal
flexion.

Shoulder internal/external rotation cannot be recovered from the
upper-arm vector alone, since axial spin of the humerus does not move the
elbow. We use the forearm as a proxy, projecting it onto the plane
perpendicular to the upper-arm axis:
\begin{equation}
\mathbf{f}_\perp = \hat{\mathbf{f}} - (\hat{\mathbf{f}}\cdot\hat{\mathbf{u}})\hat{\mathbf{u}}, \qquad
\theta_{rot} = \operatorname{atan2}(\mathbf{f}_\perp\!\cdot\!\mathbf{e}_1,\ \mathbf{f}_\perp\!\cdot\!\mathbf{e}_2)
\end{equation}
for an orthonormal basis $(\mathbf{e}_1, \mathbf{e}_2)$ of that plane.
This projection is only well-conditioned when the elbow is bent enough
that $\|\mathbf{f}_\perp\|$ is bounded away from zero; the system gates
the estimate as unreliable below $25^\circ$ of elbow flexion
(\texttt{ROTATION\_RELIABLE\_THRESHOLD}) and returns a flagged
placeholder rather than a noise-dominated angle. This threshold and its
consequences for evaluation are exercised directly by our own test suite
(Section~\ref{sec:results-tests}).

\subsection{Bilateral Symmetry}
\label{sec:bilateral}
Rather than duplicating the above formulas with flipped signs for the
left arm, the left arm's torso-frame vectors are reflected across the
sagittal plane, $(v_x,v_y,v_z)\mapsto(-v_x,v_y,v_z)$, before applying the
right-arm formulas unchanged. A reflected left arm is geometrically
indistinguishable from a right arm, so the same equations yield
anatomically mirrored conventions (abduction positive $=$ away from the
midline, internal rotation positive, for both arms) without a second code
path. Elbow flexion needs no reflection, since a dot product is
reflection-invariant.

\subsection{Temporal Filtering}
\label{sec:filtering}
Three causal filters are implemented per angle channel. The moving
average, $y[n]=\frac1W\sum_{k=0}^{W-1}x[n-k]$, is a cheap baseline with
$(W\!-\!1)/2$ frames of group delay. Savitzky-Golay
\cite{savitzky1964smoothing} fits a degree-$p$ polynomial to a window and
evaluates it at the most recent sample, preserving curvature and peak
timing better than a flat mean. The two-state Kalman filter models state
$\mathbf{x}=[\theta,\dot\theta]^{\!\top}$ under a constant-velocity
transition $F=\begin{bsmallmatrix}1&dt\\0&1\end{bsmallmatrix}$ with
measurement matrix $H=[1\ 0]$, discretized white-noise-acceleration
process covariance
$Q = q\begin{bsmallmatrix}dt^4/4 & dt^3/2\\ dt^3/2 & dt^2\end{bsmallmatrix}$,
and the standard predict/update recursion
\begin{align}
\mathbf{x}^- &= F\mathbf{x}, & P^- &= FPF^{\!\top}+Q \\
K &= P^-H^{\!\top}(HP^-H^{\!\top}+R)^{-1} \\
\mathbf{x} &= \mathbf{x}^- + K(z-H\mathbf{x}^-), & P &= (I-KH)P^-.
\end{align}
Because the state includes angular velocity, the predict step
extrapolates through fast motion, reducing lag relative to the moving
average. Filtering is reset at sequence/tracking-loss boundaries so it
never smooths across a discontinuity, and is evaluated as an explicit
ablation factor (Section~\ref{sec:results-filters}) rather than folded
into framework-accuracy numbers.

\subsection{Calibration}
\label{sec:calibration}
A three-tier calibration pipeline maps raw estimated angles to a user's
range of motion and to Unity's normalized muscle space $[-1,+1]$. Tier 1
(static) has the user hold four reference poses -- arm down, arm forward
($90^\circ$ flexion), arm to the side ($90^\circ$ abduction), elbow bent
($90^\circ$ flexion) -- from which a per-DOF affine map
$\text{calibrated} = (\text{raw} + \text{offset})\times\text{scale}$ is
fit, with offset zeroing the arm-down pose and scale mapping the observed
range onto the $90^\circ$ anatomical reference. Tier 2 (dynamic) records
a free range-of-motion sweep and refines the min/max bounds from observed
extrema. Tier 3 (online auto-expansion) grows the recorded range by
$5^\circ$ whenever a live reading exceeds it, so the avatar never
hard-clips for a more flexible user without a full recalibration.
Calibration state is persisted as JSON between sessions. Because the same
affine calibration structure -- a per-DOF offset and scale from a small
set of reference poses -- is exactly what a wearable exoskeleton's joint
encoders would need to be aligned to an anatomical zero, this module is
written to be reusable as-is for that future integration, not merely
analogous to it.

\subsection{Communication Protocol and Unity Integration}
Vision-side and Unity-side processes communicate over UDP at a
configurable rate (default 30~Hz, minimum spec $\geq 20$--$30$~Hz). Each
packet is one newline-terminated line. Two formats are supported: a
single-arm packet \texttt{S,<flex>,<abd>,<rot>,<elbow>\textbackslash n}
and a bilateral packet
\texttt{B,<r\_flex>,...,<r\_elbow>,<l\_flex>,...,<l\_elbow>\textbackslash n}
mirroring the right side while an occluded side holds its last known
value. On the Unity side, a background thread performs the blocking
socket receive and hands validated packets to the main thread through a
double-buffered, lock-protected struct so the render loop never blocks on
network I/O; \texttt{AvatarMuscleController} then maps each DOF's degrees
to Unity's Humanoid muscle space via a configurable per-DOF linear map and
a \texttt{Mathf.SmoothDamp} stage for frame-rate-independent smoothing,
using \texttt{HumanPoseHandler} rather than hardcoded bone transforms so
the same script works with any Humanoid-rigged avatar.

\section{Evaluation Methodology}
\label{sec:eval-harness}

\subsection{Metrics}
For predicted/ground-truth angle pairs $\{(p_i, g_i)\}_{i=1}^{N}$ (frames
with either signal missing excluded, never imputed), the harness computes
Mean Absolute Error (MAE), Root Mean Squared Error (RMSE), signed bias
$\frac1N\sum(p_i-g_i)$, Pearson correlation $r$, coefficient of
determination $R^2$, Percentage of Correct Keypoints at
$5^\circ/10^\circ/15^\circ$ (fraction of frames with $|p_i-g_i|<\theta$),
and jitter (mean $|\Delta p|$ frame-to-frame). MPJAE is the macro-average
of MAE across the four joint DOF. Angular differences use a circular
form, $\Delta_{circ} = ((p-g)+180)\bmod 360 - 180$, so a true angle path
crossing the $\pm180^\circ$ branch cut of the \texttt{atan2}-based
decomposition is not scored as an artificially large error.

\subsection{Statistical Protocol}
For comparing two systems on the same frames, the harness runs a paired
$t$-test and, as a distribution-free alternative given the heavy-tailed
nature of pose error, the Wilcoxon signed-rank test on per-frame
absolute-error differences, reports Cohen's $d_z$ as an effect size,
computes percentile bootstrap confidence intervals, and applies
Holm-Bonferroni correction across the resulting family of tests.

\subsection{Reproducible Experimental Protocol}
Dataset-backed evaluation follows the Human3.6M standard split -- train
S1/S5/S6/S7 for parameter tuning, validate on S8 for filter/model
selection, test on S9/S11 touched exactly once -- with an alternative
Leave-One-Subject-Out protocol for generalization checks, and an explicit
\texttt{assert\_no\_leakage} guard that raises if a tuning subject
reappears in the test set.

\subsection{Publication-Grade vs. Synthetic Labeling}
The dataset-backed harness (\texttt{evaluate\_h36m.py},
\texttt{evaluate\_panoptic.py}) distinguishes three prediction sources:
\texttt{live} (real pose estimators run on real extracted video frames --
the only publication-grade mode), \texttt{csv} (previously computed real
predictions, publication-grade if genuinely produced that way), and
\texttt{synthetic} (predictions simulated as ground truth plus
literature-calibrated Gaussian noise, for pipeline verification only).
Every synthetic-mode output is tagged \texttt{publication\_grade=false} in
its exported metadata and is printed with an explicit warning banner; the
harness never silently presents a simulated number as an experimental
one. We adopt this same labeling discipline for every number reported
below.

\section{Results: Self-Contained Correctness Verification}
\label{sec:results-tests}

The repository's 50-test suite (\texttt{tests/test\_pose\_estimators.py},
22 tests, and \texttt{tests/test\_evaluation.py}, 28 tests) requires no
camera, no GPU, and no external dataset -- it constructs synthetic
landmark configurations with known geometry and checks the resulting
angles analytically. We ran the complete suite in the delivered
repository (\texttt{python -m unittest tests.test\_pose\_estimators
tests.test\_evaluation}); all 50 tests pass. The tests that matter most
for the claims in Section~\ref{sec:angles}--\ref{sec:bilateral}:
\begin{itemize}
\item \textbf{Reference-pose geometry.} Arm hanging straight down yields
flexion, abduction, and elbow flexion each within $1^\circ$ of
$0^\circ$; arm raised to horizontal in front of the torso yields flexion
within $2^\circ$ of $90^\circ$; arm raised to horizontal at the side
yields abduction within $2^\circ$ of $90^\circ$; a $90^\circ$-bent elbow
with the forearm horizontal yields elbow flexion within $2^\circ$ of
$90^\circ$. These are noiseless analytic checks -- they verify the
\emph{formulas} are geometrically correct, not that a real camera + pose
network will reproduce them under tracking noise (Section~\ref{sec:limitations}).
\item \textbf{Physical constraints.} Elbow flexion is never negative
across randomized synthetic configurations, as required by
Section~\ref{sec:angles}'s derivation.
\item \textbf{Rotation reliability gate.} Shoulder rotation is correctly
flagged unreliable when synthetic elbow flexion is held below the
$25^\circ$ threshold.
\item \textbf{Torso frame orthonormality.} $R^{\!\top}R=I$ and
$\det(R)=+1$ hold to floating-point precision across randomized
non-degenerate shoulder/hip configurations; a degenerate configuration
(zero-length shoulder or hip baseline) correctly returns \texttt{None}
rather than a degenerate frame.
\item \textbf{Filter behavior.} The moving-average filter measurably
reduces injected Gaussian noise; the Kalman filter initializes to the
first observed value and converges toward a constant input; all filters
correctly reset their internal state when \texttt{reset()} is called
(the tracking-loss code path).
\item \textbf{MoveNet COCO$\to$MediaPipe remapping.} The 17-keypoint
COCO output's $(y, x, \text{score})$ ordering is correctly transposed to
MediaPipe's $(x, y, \ldots)$ convention, and each of the eight remapped
joints lands at its documented target index -- the exact bug class
described in Section~\ref{sec:limitations} as a hazard of mixing
keypoint schemas.
\item \textbf{Metrics correctness.} MAE scales with injected noise as
the theoretical expectation $\sigma\sqrt{2/\pi}$ for zero-bias Gaussian
error; MPJAE is exactly the arithmetic mean of the four per-joint MAEs;
PCK@5$^\circ$ decreases monotonically as injected noise grows; a
framework with less injected noise deterministically ranks with lower
MPJAE than one with more.
\end{itemize}

400-sample, 30~Hz signal in three segments -- a static hold at

150--250, for step-response lag), and a $1$~Hz sinusoidal sweep (frames
250--400, for tracking fidelity) -- and evaluates each filter

Table~\ref{tab:filters} reports its unmodified console output, and

All six configurations meet the $\leq 3$--$5^\circ$ static-pose variance
target from Section~\ref{sec:calibration-target}; the Kalman filter meets
it with roughly a third of the moving average's static standard
deviation and with negligible step-response lag, because its velocity
state extrapolates through the step rather than averaging across it. The
Kalman filter's RMSE over the \emph{full} signal is nonetheless the
highest of the six: the benchmark's RMSE is computed over the whole
400-sample signal including the sinusoidal-tracking segment, and a
responsive filter that tracks a fast-moving true signal closely still
accumulates squared error from following genuine motion, whereas a
heavily lagged filter can appear to have lower RMSE on a bounded
sinusoid purely by under-reacting; Savitzky-Golay's intermediate RMSE
reflects the same tradeoff at a different point on the smoothness/lag
curve. This is exactly the ablation discipline described in
Section~\ref{sec:filtering}: filter choice is a lag/smoothness tradeoff,
not a single scalar to be minimized, and the right operating point
depends on whether the downstream use case (visual smoothness for an
avatar vs.\ fast-changing calibration reference for an exoskeleton
controller) values lag or noise rejection more.

\section{Results: Occlusion Robustness}
\label{sec:results-occlusion}

\texttt{src/evaluation/occlusion\_test.py --synthetic} generates 3{,}000
frames of synthetic ground truth (independent sinusoidal trajectories per
DOF, not tied to any external dataset), simulates each framework's raw
predictions as ground truth plus a literature-calibrated Gaussian noise
profile per DOF (the same profiles used by the pipeline's own synthetic
smoke tests, not measurements of the actual frameworks), then randomly
occludes a fraction of frames and applies zero-order hold -- the same
behavior the live pipeline exhibits when a pose estimator returns no

MAE and RMSE stay essentially flat as the occlusion rate rises, by
construction: zero-order hold repeats the last valid estimate, which for
a slowly varying sinusoidal ground-truth trajectory is usually still
close to the true value, so an unconditional MAE against ground truth
does not surface the degradation. Drift -- the mean absolute distance
between the held (stale) estimate and the true value specifically during
occluded frames -- is the metric that does surface it, and it grows
close to linearly with the occlusion rate for all three simulated
frameworks, as expected for hold-based dead-reckoning under a moving
target. We report this contrast deliberately: it is a concrete
illustration of Section~\ref{sec:eval-harness}'s point that the choice of
metric, not only the underlying system, determines what a benchmark
appears to show, mirroring the same lesson we apply to the temporal
filter benchmark in Section~\ref{sec:results-filters}.

\subsection{Static-Pose Calibration Target}
\label{sec:calibration-target}
The project's static-pose stability target -- angle variance within
approximately $\pm3$--$5^\circ$ after filtering (from the original
project specification's Month-4 requirement) -- is the threshold plotted
in Table~\ref{tab:filters}. All filter configurations we tested meet it
on the synthetic static-hold segment; Section~\ref{sec:limitations}
discusses why this does not by itself establish real-camera accuracy.

\section{Dataset Access and Reproducing Real-Data Validation}
\label{sec:dataset-access}

Human3.6M \cite{ionescu2014human36m} requires researcher registration at
\url{vision.imar.ro}; that registration path was not completed for this
study. CMU Panoptic Studio \cite{joo2015panoptic} distributes a subset of
sequences without a registration gate, so we attempted to fetch a sample
sequence directly from the data server
(\texttt{domedb.perception.cs.cmu.edu}) from the development environment
used for this work. The request was rejected at the network layer (HTTP
403 on both a plain GET and the HTTPS CONNECT tunnel) by that
environment's outbound network policy, which is more restrictive than
general internet access -- unrelated repositories and GitHub-hosted
content over HTTPS were reachable from the same environment at the same
time, confirming the block was specific to that host rather than a
general connectivity failure. We report this rather than substituting a
different, unverified number, consistent with the authenticity standard
Section~\ref{sec:eval-harness} sets for the rest of this paper.

\label{sec:reproducing}
The evaluation harness that would consume such data is not hypothetical:
it is delivered in full in this repository and is exercised end to end
by the passing synthetic-mode tests of Section~\ref{sec:results-tests}
and the requirement (enforced by \texttt{report\_export.py}'s metadata
and the \texttt{SYNTHETIC\_WARNING} banner) that only real, live-mode
predictions may be reported as \texttt{publication\_grade}. With access
to either dataset, the same numbers this paper's structure anticipates
can be produced with:
\begin{verbatim}
python -m scripts.evaluate_h36m \
  --h36m_dir data/dataset/h3.6m/dataset \
  --frame_dir data/dataset/h3.6m/frames \
  --mode live \
  --frameworks mediapipe movenet_lightning posenet
\end{verbatim}
or, for the non-registration-gated Panoptic Studio substitute:
\begin{verbatim}
python -m scripts.evaluate_panoptic \
  --sequence_dir <extracted_panoptic_sequence> \
  --camera 00_00 \
  --frameworks mediapipe movenet_lightning posenet
\end{verbatim}
Both scripts run the real pose estimators frame by frame, compute the
metrics of Section~\ref{sec:eval-harness}, run the full statistical
protocol, and export a reproducibility record (library versions, git
commit, random seed, and a \texttt{publication\_grade} flag) alongside
the results, so that a future run's numbers are independently checkable
rather than only trusted.

\section{Discussion and Limitations}
\label{sec:limitations}

\textbf{No real-camera or real-dataset accuracy claim is made.} Every
number in Sections~\ref{sec:results-tests}--\ref{sec:results-occlusion}
is either an analytic correctness check on synthetic, exactly-known
geometry, or a benchmark against a synthetic signal with
literature-calibrated (not measured) per-framework noise. None of them
substitutes for the real-dataset validation described in
Section~\ref{sec:dataset-access}, which this environment could not
produce. A reader should treat the synthetic occlusion and filter
numbers as evidence the \emph{pipeline mechanics} behave as designed
(filters reduce jitter, holds drift as expected, metrics respond to
noise in the expected direction), not as an accuracy claim about
MediaPipe, MoveNet, or PoseNet on real video.

\textbf{Flexion-angle singularity.} The ZXY decomposition's second
singularity, noted in Section~\ref{sec:angles}, occurs as
$\theta_{abd}\to90^\circ$: both $v_y$ and $v_z$ in
$\theta_{flex}=\operatorname{atan2}(-v_z,-v_y)$ approach zero
simultaneously, so flexion becomes acutely sensitive to small measurement
noise near full abduction. This is an unavoidable coordinate pole for any
two-angle parameterization of a direction vector (the rotational analogue
of longitude's degeneracy at the geographic poles), not a bug, but it
means flexion accuracy should be expected to degrade specifically during
near-full-abduction poses independent of tracking quality.

\textbf{Rotation observability.} The forearm-proxy method for shoulder
rotation (Section~\ref{sec:angles}) is, by construction, only meaningful
above the elbow-flexion reliability threshold; any monocular system using
a comparable proxy inherits the same limitation, and any evaluation of it
should report the fraction of frames for which the estimate was
geometrically valid rather than an unconditional error.

\textbf{Depth ambiguity.} MediaPipe's pseudo-3D $z$ coordinate is a
relative depth estimate from a single image and is used only where
strictly necessary (the coordinate frame itself is built entirely from
in-image-plane vectors); MoveNet and PoseNet provide no depth channel at
all and are padded with zero-visibility placeholders for the corresponding
entries, meaning their angle estimates rely more heavily on the 2D
projection and should be expected to be more view-dependent.

\textbf{Simplified kinematic model.} The arm is modeled as a two-link
rigid chain (upper arm, forearm) with a single-DOF elbow and a
3-DOF-via-proxy shoulder, following \cite{koritnik2003kinematic} and
\cite{biryukova2000kinematics}; this is adequate for a real-time
avatar-control and calibration-reference signal but is not a
biomechanically complete model of the shoulder complex (no separate
scapulohumeral rhythm, no clavicular elevation).

\textbf{Scope of the exoskeleton-calibration claim.} We designed the
calibration module (Section~\ref{sec:calibration}) to be structurally
reusable for exoskeleton sensor calibration -- the same affine per-DOF
map from a small set of reference poses -- but no wearable exoskeleton
was available to validate that reuse in practice; this is future work,
consistent with the original project specification's framing of this
system as a foundational platform rather than a finished
exoskeleton-calibration product.

\section{Conclusion}
We presented a monocular vision-based framework for anatomically
consistent, bilateral shoulder and elbow joint-angle estimation, temporal
filtering, calibration, and real-time Unity avatar control, with a
complete mathematical derivation of the torso-frame construction, the
ZXY angle decomposition, and all three temporal filters. Every
quantitative result in this paper -- 50 passing correctness tests, a
synthetic filter benchmark, and a synthetic occlusion-robustness study --
was generated by running the delivered code in this repository during
this work, and we report explicitly, rather than paper over, that
real-dataset validation against Human3.6M or CMU Panoptic Studio was not
possible from the development environment used here because both data
sources were unreachable (one by registration gate, one by network
policy). The complete, unmodified evaluation harness capable of producing
that validation -- identical metric definitions, statistical protocol,
and publication-grade labeling discipline used throughout this paper -- is
part of the delivered repository, so that real-data validation is a
single documented command away rather than a rewrite. We regard the
explicit separation between what this paper measured and what its
harness is designed to measure as itself a necessary property of an
authentic research paper in this space, not a limitation to be minimized.
